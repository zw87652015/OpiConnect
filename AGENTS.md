# OpiConnect

Android notifications mirrored to Apple Watch. `docs/PROTOCOL.md` is the authoritative
spec for crypto, pairing, BLE, and the relay API; `docs/test-vectors.json` covers every
implementation (generated by `docs/gen-test-vectors.mjs`).

## Layout

- `watch/` — watchOS app (Xcode 16+ project, synchronized folders): `OpiConnect`
  watchapp2-container, `OpiConnect Watch App`, `NotificationService` (NSE), `Shared`
  (compiled into app + NSE), `OpiConnectTests`. Shared schemes: "OpiConnect Watch App"
  (run/test), "OpiConnect" (archive). `Local.xcconfig` is git-ignored (DEVELOPMENT_TEAM,
  BUNDLE_PREFIX).
- `android/` — Kotlin + Compose app; `core/` is pure Kotlin (JVM-unit-testable).
- `server/` — Node 22 single-file APNs relay (`index.mjs`) + `test.mjs` + deploy README.

## Verify

- Watch (on this Mac, Xcode 27):
  `xcodebuild test -project watch/OpiConnect.xcodeproj -scheme "OpiConnect Watch App" -destination 'platform=watchOS Simulator,name=<watch sim>' CODE_SIGNING_ALLOWED=NO`
  and `xcodebuild build -project watch/OpiConnect.xcodeproj -scheme "OpiConnect" -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO` (confirms the container embeds the watch app + NSE).
- TestFlight: `scripts/testflight.sh` archives the "OpiConnect" container and uploads it
  (`DESTINATION=export` for a local .ipa only). The container target must keep
  `SKIP_INSTALL = NO`, otherwise the archive's Products folder is empty.
- Server: `node --check server/index.mjs && node --test server/test.mjs`
- Android: built on the user's Windows machine — `gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` (minSdk 31; lint catches NewApi).
  This Mac only has JDK 11; do not try to run AGP here.
- Android on Windows: JAVA_HOME is unset and the Android Studio JBR (Java 25) is too new for
  Gradle 8.11; run with `JAVA_HOME=$USERPROFILE/.jdks/ms-17.0.21.0.2`.

## App Store

- Store name is **OpiLink**: user-facing strings say OpiLink, while targets, modules, bundle IDs,
  the URL scheme, and protocol identifiers keep "OpiConnect".
- Listing materials live in `appstore/` (listings, review notes, App Store Connect answers,
  privacy policy, screenshots).
- Screenshots: use the Debug build on the "Apple Watch Ultra 4 (49mm)" sim (422×514, same size
  in every localization) and run
  `xcrun simctl launch --terminate-running-process <udid> <bundle id> -OpiDemo en|zh -OpiDemoRoute home|notifications|detail|otp|calendar|music|findphone|pairing|guide|settings|bottom|paywall|plans`
  (for zh, add `-AppleLanguages "(zh-Hans)" -AppleLocale zh_CN`), then
  `xcrun simctl io <udid> screenshot`. `DemoMode.swift` is DEBUG-only and keeps state in memory.
  `plans` is the paywall without its header, so the subscription list fits on one screen. StoreKit
  draws that list from the sandbox storefront, so it stays in English whatever `-AppleLanguages` says.
  Once the app has been run from Xcode, the sim keeps using `watch/Products.storekit` (local test
  prices) even for `simctl launch`, because Xcode copies it into the sim. `Products.storekit` must use
  Xcode's schema (subscription groups list `subscriptions`, not `products`), otherwise storekitd
  can't read it and the paywall says the subscription is unavailable.
  This Xcode 27 install has no Simulator GUI, so you can't scroll; add demo routes instead.
  App Store Connect rejects watch screenshots at other sizes (for example 374×446 from a 42mm watch).

## Protocol changes

Any change to crypto/pairing/BLE/relay semantics must update `docs/PROTOCOL.md`,
regenerate vectors (`node docs/gen-test-vectors.mjs`), and keep the Swift and Kotlin
vector tests passing on both platforms.
